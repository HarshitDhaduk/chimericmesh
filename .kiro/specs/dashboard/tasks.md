# Implementation Plan: dashboard (V1)

Requirements: [requirements.md](requirements.md). Design: [design.md](design.md). Property numbers below are the numbered Correctness Properties in the design (1 to 9, all Python; JavaScript is covered by the in-page `#selftest` and Manual steps, not by Hypothesis).

Preconditions: the `store`, `services`, `connectors`, `discovery` and `auto-approval` modules are merged, so `Hub` implements `StateView.events_after` and `recent`, `create_app` builds the registry and the routers, and `index.html` already carries the interim token prompt of `services` task 7.10. `agent-loop` is not required for the build: the only route of it that the page uses is `/permissions-snippet`, which has a fallback (design, "Needs from agent-loop"); the live-log backlog comes from this module's own stream `tail`. `tests/unit/route_owners.py` (created by `agent-loop` task 8.2) may not exist yet: if it is absent when task 3.2 or 3.3 runs, those tasks write the two dashboard rows into a `DASHBOARD_ROUTES` list in `tests/unit/route_owners_dashboard.py` and record in the final checkpoint that `agent-loop` must import it; if it exists, append the two rows to it. This module edits `api.py` and `index.html` on top of those modules' results. Nothing here is committed by the agent. `examples/legacy_app/upstream.py` (the user's uncommitted demo edit), every `requirements.md`, `docs/v1-capability-map.md`, `.kiro/specs/store/` and the worktree `e:\Projects\Kiroween-2026-store` are never touched.

Conventions for every task: write the tests first and watch them fail, then implement; run the new tests and `python -m pytest -q`; no task edits an existing test except 4.3 (`tests/unit/test_dashboard_token.py`, created by `services` task 7.10, design O7), the rows added to `tests/unit/test_dependency_direction.py` (1.1) and the two rows added to `tests/unit/route_owners.py` (3.2, 3.3). Tasks marked `*` (Kiro's optional marker, `- [ ]*`) are optional property tests that may be skipped for a faster first pass; every requirement is also covered by a non-optional example test. Every property task **not** marked `*` is required: task 2.4 (properties 1, 2, 3). The optional one is 2.5 (properties 4 to 9). Success Criterion 3 names property 1; it is required. Stack: Python 3.11+, stdlib, FastAPI and Starlette in `web/stream.py` only, pytest, Hypothesis (already in the `dev` extra). Browser side: one HTML file, inline CSS and one inline script, no build step, no JavaScript test runner, no Node. Page rules for every page task: no `innerHTML`, `outerHTML`, `insertAdjacentHTML` or `document.write` (use `el(tag, cls, text)` and `textContent`), no external origin, `setAttribute` only with a literal non-URL name from the design's list. New Python files are under `src/chimericmesh/web/` and new tests under `tests/unit/` or `tests/pbt/` unless a path is given. Each sub-task touches at most five files. A task line that begins `Manual browser check` is a human step; it may use headless Edge (`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`) and is never skipped silently: the final checkpoint (10.3) lists them. Do not start a server in a test run except through `httpx.ASGITransport`.
